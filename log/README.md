
日志系统
===============

单例日志，提供同步与异步两种写入方式，支持按天与按行数轮转。

结构
---------------

异步写入由**缓冲池 + 一个写盘线程**构成：

| 角色 | 说明 |
|:--|:--|
| `m_front` | 当前写入块。调用方在此追加，追加动作就是一次 `memcpy` |
| `m_pending` | 已写满、等待落盘的块，先进先出。有且只有写盘线程会取走它，文件内容的顺序因此等于写入顺序 |
| `m_free` | 空闲块 |

池的大小固定为 9 块（1 块当前写入 + 8 块可排队），日志在内存中的上界即
`9 × batch_buf_size`（默认 576 KiB）。池在 `init` 时一次性分配并预留容量，
此后**写入路径与落盘路径都不再分配内存**。

写入路径
---------------

1. 取时间（`localtime_r`，可重入）
2. 把时间前缀与格式化内容写进**线程私有的定长缓冲**，与其它线程无争用
3. 取一次锁，把这一行 `memcpy` 进 `m_front`；放不下就换块，并唤醒写盘线程

因此写入路径上没有系统调用，也没有内存分配；持锁区间只有一次 `memcpy` 与几个计数。
唤醒只在换块时发生——逐行唤醒会把刚省下的系统调用又加回来。

格式化的缓冲是编译期定长的数组而非按配置扩容的容器：容量若来自运行期配置，
第 2 步就得无锁读一个会被 `init` 改写的量（数据竞争），或者为它加锁。
把取值范围固定下来（`buf_size` 夹到 `[128, 4096]`），这个问题就不存在了。

落盘与轮转
---------------

写盘线程在满足下列任一条件时醒来：缓冲块写满，或到达 `flush_interval`。
醒来后把 `m_pending` 整体取出，**在锁外**用一次 `fwrite` 写出整块。

「块没满但已经等够久了」正是定时唤醒来解决的问题，因此每次醒来都会先把
`m_front` 里未满的那一块一并交出去——只排空写满的块会让日志长期留在内存里。

文件轮转（按天、按 `split_lines` 行数）也在写盘线程完成，且位于排空之后，
顺序因此得以保持。`split_lines` 是**软**上限：判据是「整块写下去会不会越过」，
文件可能多出不到一块的行数，换来的是写盘侧永远只做整块写出，不必按行切分。

背压
---------------

池中的块都在等待落盘时，新到的行会被丢弃并计数，由写盘线程在下次落盘时
写成一行「已丢弃 N 行日志」——丢失在文件里可见，而不是无声无息。
这里不同步写盘：那会把一次磁盘写压到 Reactor 线程上。

同步方式（`write_mode = 0`）
---------------

不做缓冲，每一行直接落到文件（写文件的部分由锁串行化，顺序即取得锁的顺序），
保持「写入即落盘」的语义。代价是每行一次写入系统调用——异步方式的收益全部来自
这一项的省去，因此**默认写入方式是异步**。

退出
---------------

`SIGTERM` → signalfd → 事件循环退出 → `WebServer` 析构中先 join 子 Reactor 线程
（此后无人再写日志），再排空日志；`Log` 自身析构时还会幂等地再排空一次。
进程崩溃或被 `SIGKILL` 时最多丢掉一个 `flush_interval` 的日志。
