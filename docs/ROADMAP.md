# 优化路线图

本文档记录 NovaServer 的优化目标、技术方案与推进进度。

## 一、背景

NovaServer 当前采用一套经典的高并发服务器结构：**线程池 + 非阻塞 IO + epoll 事件驱动 + 状态机协议解析**，配合升序链表定时器回收非活动连接。这套结构在其适用场景下可以稳定工作，但在持续演进中积累了一些需要系统性解决的问题：

- **并发约束依赖运行时时序**：连接状态与共享数据的访问缺少统一的归属约定，部分路径的正确性由执行顺序的偶然性保证，而非结构性约束
- **生命周期管理分散**：连接、定时器、内存映射的释放路径存在多处重叠，容易产生重复释放或悬垂引用
- **缓冲区尺寸固定**：请求处理受限于固定的读缓冲大小，超出后连接被直接关闭，制约了大请求体与大文件上传
- **代码风格停留在早期标准**：未使用语言标准之外的现代设施，手工内存管理遍布，且缺少统一的格式化与编译告警约束
- **协议实现不完整**：URL 未解码、部分方法未支持、若干边界缺少校验
- **工程设施缺失**：没有构建系统、单元测试与持续集成，任何改动都缺少回归保障
- **性能特征不可观测**：未建立性能基线，无法量化评估改动带来的影响

本次优化在**保持 HTTP 协议处理语义不变**的前提下，统一工程基础与代码规范，修复确定性缺陷，重建并发模型，并补齐验证设施。

## 二、技术目标

| 目标 | 说明 |
|:--|:--|
| 正确性 | 并发行为由结构保证，消除数据竞争与悬垂引用 |
| 健壮性 | 完善输入校验与边界处理，规范错误响应，补齐协议实现 |
| 可扩展性 | 解除固定缓冲区限制，支持大请求体与大文件上传 |
| 代码质量 | 统一语言标准与格式规范，消除手工内存管理与不安全调用 |
| 可验证性 | 建立单元测试与持续集成，为改动提供回归保障 |
| 可观测性 | 完善日志系统，建立可复现的性能基线与对比数据 |

## 三、现有架构

### 运行结构

| 模块 | 位置 | 职责 |
|:--|:--|:--|
| 服务器主类 | `webserver.cpp` / `webserver.h` | 持有监听套接字与 epoll 实例，主循环中分发事件，调度定时器 |
| 协议处理 | `http/http_conn.cpp` | 每连接一个对象，三状态状态机解析请求，`mmap` + `writev` 发送响应 |
| 线程池 | `threadpool/threadpool.h` | 半同步/半反应堆模型，主线程 accept 后投递任务 |
| 定时器 | `timer/lst_timer.cpp` | 升序双向链表管理超时连接，`SIGALRM` + socketpair 触发检查 |
| 数据库 | `CGImysql/sql_connection_pool.cpp` | 连接池单例，RAII 方式借用与归还 |
| 日志 | `log/log.cpp` | 单例日志，支持同步与异步两种写入方式 |

### 请求处理流程

```
epoll_wait
  └─ 读事件 → http_conn::read_once()  读入缓冲区
       └─ process_read()  状态机解析：请求行 → 头部 → 内容
            └─ do_request()  路由：静态资源 / 登录注册 / 文件上传
       └─ process_write() 组装响应头，映射静态文件
  └─ 写事件 → http_conn::write()  writev 发送
       └─ 完成后重置连接状态或关闭
```

### 待改进的问题

**并发与生命周期**

1. **连接侧触发模式未按配置生效** —— 注册文件描述符时读取的成员变量尚未完成赋值，实际始终按 LT 注册，`-m` 参数中的 ET 组合从未真正生效
2. **定时器链表缺少线程约束** —— 主线程遍历链表与工作线程修改链表之间没有同步，属于并发访问未保护
3. **资源释放路径重叠** —— 连接关闭与定时器回调均会释放同一描述符，且缺少幂等保护，描述符被复用后可能误操作新连接
4. **超时回调持有裸指针** —— 定时器指向静态数组元素，缺少对象失效后的安全丢弃机制
5. **读写路径存在忙等** —— Reactor 模式下主线程轮询标志位等待工作线程完成，持续占用 CPU 且无法保证跨线程可见性
6. **描述符耗尽无兜底** —— ET 模式下 `accept` 因 `EMFILE` 失败后不会再触发事件，服务将永久失去接受连接的能力
7. **连接对象预分配** —— 按最大连接数静态分配连接对象数组，每个对象携带固定缓冲区，造成较大的常驻内存

**正确性与健壮性**

8. **日志缓冲区越界写** —— 格式化截断后仍向缓冲区写入终止符，恰好越过分配边界
9. **读取返回值漏判** —— LT 分支未处理 `recv` 返回负值的情况，会先更新读索引再返回
10. **成员未初始化** —— 指向请求体的指针未在初始化流程中重置，判空逻辑不可靠
11. **共享用户表同步不对称** —— 写侧加锁而读侧未加锁
12. **静态资源路径未规范化** —— 拼接前未做规范化与根目录边界校验
13. **数据库查询字符串拼接** —— 未使用参数化查询
14. **口令明文存储** —— 直接比对明文
15. **参数解析存在固定偏移假设** —— 按固定下标提取字段，缺少边界校验
16. **错误响应与状态码不匹配** —— 部分错误路径返回的状态码与语义不符
17. **固定读缓冲区** —— 固定 2KB，超出后被判定为对端关闭
18. **配置硬编码** —— 数据库连接信息写在源码中

**协议实现**

19. **URL 未解码** —— `%XX` 序列按字面处理，含转义字符或非 ASCII 的路径无法正确匹配
20. **未支持 HEAD 方法** —— 解析阶段直接判定为错误请求
21. **头部长度与 `Content-Length` 缺少校验** —— 未处理超长头部、非数字或异常取值的长度字段

**功能完整性**

22. **上传文件不可访问** —— 文件写入 `./upload/`，而静态资源根目录为 `./root/`，上传后无法通过 HTTP 查看
23. **上传缺少类型与大小约束** —— 仅做了路径分隔符剥离，没有扩展名白名单与体积上限

**代码规范**

24. 大量使用 `strcpy` / `strcat` / `sprintf` 等无长度校验的函数
25. 头文件中存在全局 `using namespace std`
26. `malloc` / `free` 与 `new` / `delete` 混用
27. 以 `assert` 承担运行时错误校验，在 Release 构建下失效
28. 只读方法普遍缺少 `const` 限定

## 四、优化计划

> 阶段划分的原则：**与并发架构无关的改动尽量前置**，避免在架构重构中返工。

### 阶段零 · 基线建立

在改动任何代码之前，先测量并归档当前性能特征，作为后续所有优化的对比基准。

| 采集项 | 方法 |
|:--|:--|
| 吞吐与延迟 | webbench 压测，覆盖 `-m 0/1/2/3` 触发模式组合 |
| 常驻内存 | `ps` 记录 RSS 与 VSZ |
| 空载 CPU | 保持一条空闲长连接，观察 CPU 占用 |
| 线程数 | `top -H` 或 `pstree` |
| 连接上限 | 逐步加压，记录可稳定维持的并发连接数 |

数据连同测试环境、编译选项与完整命令归档至 `docs/changes/000-baseline.md`。

### 阶段一 · 工程基础与代码规范

目标是建立可持续的开发基础，此阶段的改动**不涉及行为变化**。

| 改进项 | 说明 |
|:--|:--|
| 构建系统 | 以 CMake 替代 Makefile，支持 Debug/Release 与 Sanitizer 构建目标 |
| 语言标准 | 统一迁移到 **C++17**，允许使用智能指针、`std::function`、`std::mutex`、`std::chrono` 等设施 |
| 代码格式化 | 引入 `clang-format` 与 `.clang-format` 配置，全项目统一格式 |
| 编译告警 | 启用 `-Wall -Wextra`，逐项治理告警；后续视情况收紧 |
| 字符串处理 | 以 `std::string` 及有长度约束的接口替代不安全的 C 字符串函数 |
| 命名空间 | 移除头文件中的全局 `using namespace`，改用显式限定 |
| 内存管理 | 统一为 RAII 管理，消除 `malloc` / `free` 与 `new` / `delete` 混用 |
| 断言使用 | 区分「开发期断言」与「运行时错误处理」，后者改为真正的错误分支 |
| const 正确性 | 为只读方法补充 `const` 限定 |
| 测试框架 | 引入单元测试框架（GoogleTest），搭建测试目录结构与 CMake 集成 |
| 持续集成 | GitHub Actions 执行构建与测试 |

### 阶段二 · 正确性与协议完整性

修复确定性缺陷、加固输入处理，并补齐协议实现。此阶段**不改变核心数据结构与线程模型**。

| 改进项 | 现状 | 方向 |
|:--|:--|:--|
| 触发模式配置 | 注册时读取的成员尚未赋值，实际始终为 LT | 修正初始化顺序，使 `-m` 组合按预期生效 |
| 日志缓冲越界 | 截断后仍写终止符，越过分配边界 | 修正写入边界判断 |
| 读取返回值 | 未处理负值返回 | 补齐分支，区分「无数据」与「出错」 |
| 请求体指针 | 初始化流程中未重置 | 补充重置 |
| 共享用户表 | 读写同步策略不对称 | 统一同步策略 |
| 路径处理 | 静态资源路径直接拼接 | 规范化后校验是否位于根目录内 |
| 数据库访问 | 字符串拼接构造查询 | 改用参数化查询 |
| 口令存储 | 明文比对 | 引入随机盐 + 哈希 |
| 参数解析 | 固定偏移量假设，缺少边界校验 | 改为通用键值解析 |
| 配置管理 | 连接信息硬编码 | 外置为配置文件并提供示例模板 |
| 状态码语义 | 与响应内容不符 | 按 HTTP 规范修正 |
| 动态缓冲 | 固定 2KB，满即断连 | 改为可扩容缓冲，区分「缓冲满」与「连接关闭」 |
| URL 解码 | 未实现 | 支持 `%XX` 解码，并处理解码后的路径校验 |
| 请求方法 | 未支持 HEAD | 补充 HEAD 处理，复用 GET 的响应头构造 |
| 头部校验 | 缺少长度与合法性检查 | 增加头部长度上限与 `Content-Length` 合法性校验 |
| 上传闭环 | 文件写入后无法访问 | 增加上传文件的访问路由与列表展示 |
| 上传约束 | 仅有路径剥离 | 增加扩展名白名单与体积上限 |

### 阶段三 · 并发模型重构

**现状问题**：半同步/半反应堆模型中，工作线程既承担 IO 又承担业务计算。同一连接的读事件与写事件可能由不同线程处理，因此需要 `EPOLLONESHOT` 抑制重复投递，并依靠主线程轮询标志位确认处理完成——这一设计既引入了 CPU 空转，也无法为跨线程的数据可见性提供保证。

**目标模型**：主从 Reactor（one loop per thread）。主线程只负责 accept，将新连接按轮转策略分发给若干子 Reactor 线程；每个线程持有独立的 epoll 实例与事件循环。**连接的文件描述符、协议解析状态与其超时定时器全部归属所属线程**，跨线程只传递连接对象本身。这一约束成立后，「同一连接的读写串行」成为结构推论，无需附加机制。

引入的核心抽象：

| 类 | 职责 |
|:--|:--|
| `EventLoop` | 单线程事件循环：epoll 实例、唤醒机制、跨线程任务队列 |
| `Channel` | 文件描述符与关注事件的绑定，封装 `epoll_ctl` 状态维护 |
| `Acceptor` | 监听套接字管理，接收新连接，处理描述符耗尽情形 |
| `TcpConnection` | 连接生命周期、读写处理、持有协议对象 |
| `EventLoopThreadPool` | 子 Reactor 线程池与轮转分配 |
| `TimerQueue` | 基于 timerfd 的定时器队列 |

**明确不引入的抽象**（保持实现规模可控）：

| 不引入 | 理由 |
|:--|:--|
| 通用 `Buffer` 类 | 协议对象已持有读写缓冲区，且状态机的游标逻辑与之强耦合，抽象化会迫使协议层改动 |
| `Poller` 抽象基类 | 只有 epoll 一种实现，直接内联调用即可，无需虚函数层 |
| 独立 `TcpServer` 类 | 项目只有一个监听端口，其职责可直接由服务器主类承担 |
| 地址与套接字的 RAII 包装类 | 仅一种使用场景，以无状态的自由函数提供即可 |

配套改动：

- 以 **timerfd** 替代 `SIGALRM` + socketpair：统一事件源，提升精度，消除信号处理的异步限制
- 以 **eventfd** 承担跨线程唤醒，**signalfd** 接管进程退出信号
- 移除 `EPOLLONESHOT` 与主线程忙等逻辑
- 连接释放收敛为单一出口并保证幂等
- 定时器下沉至各子线程，持有连接的弱引用，并发访问在结构上不再存在
- 连接对象改为动态管理，解除按最大连接数预分配
- 描述符耗尽时预留空闲描述符兜底，保证 accept 能力不丢失
- 命令行参数语义调整：线程数参数的含义由「工作线程数」变为「子 Reactor 线程数」，原有触发模式参数保持不变
