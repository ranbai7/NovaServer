# 优化路线图

本文档记录 NovaServer 的优化目标、技术方案与推进进度。

## 一、背景

NovaServer 当前采用一套经典的高并发服务器结构：**线程池 + 非阻塞 IO + epoll 事件驱动 + 状态机协议解析**，配合升序链表定时器回收非活动连接。这套结构在其适用场景下可以稳定工作，但在持续演进中积累了一些需要系统性解决的问题：

- **并发约束依赖运行时时序**：连接状态与共享数据的访问缺少统一的归属约定，部分路径的正确性由执行顺序的偶然性保证，而非结构性约束
- **生命周期管理分散**：连接、定时器、内存映射的释放路径存在多处重叠，容易产生重复释放或悬垂引用
- **缓冲区尺寸固定**：请求处理受限于固定的读缓冲大小，超出后连接被直接关闭，制约了大请求体与大文件上传
- **工程设施缺失**：没有构建系统、单元测试与持续集成，任何改动都缺少回归保障
- **性能特征不可观测**：未建立性能基线，无法量化评估改动带来的影响

本次优化在**保持 HTTP 协议处理逻辑不变**的前提下，重建并发模型与资源管理机制，并补齐工程化设施。

## 二、技术目标

| 目标 | 说明 |
|:--|:--|
| 正确性 | 并发行为由结构保证，消除数据竞争与悬垂引用 |
| 健壮性 | 完善输入校验与边界处理，规范错误响应 |
| 可扩展性 | 解除固定缓冲区限制，支持大请求体与大文件上传 |
| 可验证性 | 建立单元测试与持续集成，为改动提供回归保障 |
| 可观测性 | 完善日志系统，建立可复现的性能基线 |

## 三、现有架构

### 运行结构

| 模块 | 位置 | 职责 |
|:--|:--|:--|
| 服务器主类 | `webserver.cpp` / `webserver.h` | 持有监听套接字与 epoll 实例，主循环中分发事件，调度定时器 |
| 协议处理 | `http/http_conn.cpp` | 每连接一个对象，三状态状态机解析请求，`mmap` + `writev` 发送响应 |
| 线程池 | `threadpool/threadpool.h` | 半同步/半反应堆模型，主线程 accept 后投递任务 |
| 定时器 | `timer/lst_timer.cpp` | 升序双向链表管理超时连接，`SIGALRM` + socketpair 触发检查 |
| 数据库 | `CGImysql/sql_connection_pool.cpp` | 连接池单例，RAII 方式借用与归还 |
| 日志 | `log/log.cpp` | 单例日志，支持同步与异步两种写入方式 |

### 请求处理流程

```
epoll_wait
  └─ 读事件 → http_conn::read_once()  读入缓冲区
       └─ process_read()  状态机解析：请求行 → 头部 → 内容
            └─ do_request()  路由：静态资源 / 登录注册 / 文件上传
       └─ process_write() 组装响应头，映射静态文件
  └─ 写事件 → http_conn::write()  writev 发送
       └─ 完成后重置连接状态或关闭
```

### 待改进的问题

1. **并发约束不完整** —— 连接侧触发模式因成员变量初始化顺序问题未按配置生效；共享用户表的读写使用了不对称的同步策略
2. **资源释放路径重叠** —— 连接关闭与定时器回调均会释放同一描述符，且缺少幂等保护
3. **定时器结构缺少线程约束** —— 主线程遍历链表与工作线程修改链表之间没有同步
4. **读写路径存在忙等** —— Reactor 模式下主线程通过轮询标志位等待工作线程完成，持续占用 CPU
5. **信号驱动的定时机制** —— `SIGALRM` 精度受限于秒级，信号合并可能导致事件丢失，且信号处理函数可执行的操作受限
6. **固定缓冲区** —— 读缓冲固定为 2KB，超出后连接被判定为对端关闭
7. **输入处理需加固** —— 静态资源路径拼接前缺少规范化，数据库查询以字符串拼接构造
8. **凭据与配置** —— 用户口令以明文存储，数据库连接信息硬编码于源码

## 四、优化计划

### 阶段一 · 正确性与健壮性

目标是先消除确定性缺陷，为后续重构建立可信基线。此阶段不改变整体架构。

| 改进项 | 现状 | 方向 |
|:--|:--|:--|
| 触发模式配置 | 连接侧注册时读取的成员尚未赋值，实际始终为 LT | 修正初始化顺序，使 `-m` 组合按预期生效 |
| 共享数据同步 | 用户表写侧加锁、读侧未加锁 | 统一同步策略 |
| 连接释放 | 关闭路径与定时器回调重叠，缺少幂等保护 | 收敛为单一出口并保证幂等 |
| 超时回调 | 定时器持有指向静态数组的裸指针 | 改为弱引用，对象失效时安全丢弃 |
| 路径处理 | 静态资源路径直接拼接 | 规范化后校验是否位于根目录内 |
| SQL 构造 | 字符串拼接 | 改用参数化查询 |
| 口令存储 | 明文比对 | 引入随机盐 + 哈希 |
| 参数解析 | 登录注册参数解析存在固定偏移量假设 | 改为通用键值解析并补边界校验 |
| 配置管理 | 数据库连接信息硬编码 | 外置为配置文件，提供示例模板 |
| 状态码语义 | 错误响应与状态码不匹配 | 按 HTTP 规范修正 |
| 缓冲区 | 固定 2KB，满即断连 | 改为可扩容缓冲，并区分「缓冲满」与「连接关闭」 |

### 阶段二 · 并发模型重构

**现状问题**：半同步/半反应堆模型中，工作线程既承担 IO 又承担业务计算。同一连接的读事件与写事件可能由不同线程处理，因此需要 `EPOLLONESHOT` 抑制重复投递，并依靠主线程轮询标志位确认处理完成——这一设计既引入了 CPU 空转，也无法为跨线程的数据可见性提供保证。

**目标模型**：主从 Reactor（one loop per thread）。主线程只负责 accept，将新连接按轮转策略分发给若干子 Reactor 线程；每个线程持有独立的 epoll 实例与事件循环。**连接的文件描述符、协议解析状态与其超时定时器全部归属所属线程**，跨线程只传递连接对象本身。这一约束成立后，「同一连接的读写串行」成为结构推论，无需附加机制。

引入的核心抽象：

| 类 | 职责 |
|:--|:--|
| `EventLoop` | 单线程事件循环：epoll 实例、唤醒机制、跨线程任务队列 |
| `Channel` | 文件描述符与关注事件的绑定，封装 `epoll_ctl` 状态维护 |
| `Acceptor` | 监听套接字管理，接收新连接 |
| `TcpConnection` | 连接生命周期、读写处理、持有协议对象 |
| `EventLoopThreadPool` | 子 Reactor 线程池与轮转分配 |
| `TimerQueue` | 基于 timerfd 的定时器队列 |

配套改动：

- 以 **timerfd** 替代 `SIGALRM` + socketpair：统一事件源，提升精度，消除信号处理的异步限制
- 以 **eventfd** 承担跨线程唤醒
- 以 **signalfd** 接管进程退出信号
- 移除 `EPOLLONESHOT` 与主线程忙等逻辑
- 定时器链表下沉至各子线程，并发访问在结构上不再存在
- 连接对象改为动态管理，解除固定的最大连接数数组预分配

### 阶段三 · 工程化与可观测性

| 项 | 说明 |
|:--|:--|
| 构建系统 | 以 CMake 替代 Makefile，支持 Debug/Release 与 Sanitizer 开关 |
| 单元测试 | 覆盖协议解析、缓冲管理、multipart 解析等核心逻辑 |
| 持续集成 | GitHub Actions 自动构建与测试 |
| 日志改造 | 双缓冲批量落盘，降低同步路径开销 |
| 性能基线 | 建立可复现的吞吐与延迟基线数据 |

## 五、验证方式

| 维度 | 方法 |
|:--|:--|
| 功能 | 走通静态资源、登录、注册、文件上传全链路 |
| 压力 | webbench，覆盖不同触发模式与线程数组合 |
| 内存正确性 | AddressSanitizer 全链路运行，确认无泄漏与越界 |
| 并发正确性 | ThreadSanitizer 在高并发连接场景下确认无数据竞争 |
| 资源占用 | 记录常驻内存、空载 CPU、线程数 |
| 超时行为 | 构造空闲连接，验证按预期时间回收且仅回收一次 |

所有性能数据需注明测试环境、编译选项与执行命令，保证可复现。
