# 017 · 核查问题修复（批次一：崩溃与越界）

> 本记录对应 `016` 第六节修复计划的**批次一**，处理其中标记为「会崩溃」的两项（A1、A2）与同源的路径截断问题（4.2）。

## 一、背景与动机

`016` 的独立核查查出 12 处问题，其中两处会让服务端崩溃，共同点是**由配置取值触发**：

| 编号 | 触发条件 | 后果 |
|:--|:--|:--|
| A1 | `root_dir` 超过 200 字符 | 每个请求越界写，Release 下核心转储 |
| A2 | 日志文件名超过 128 字符 | 启动时越界写 |

两者都不是阶段二新引入的逻辑错误，而是**既有代码里的定长缓冲区**在 `011` 把根目录与日志文件名变成配置项之后，从「几乎不可能」变成了「配置写错即触发」。同一次核查还查出 4.2：`m_real_file` 被静默截断后仍用于 `stat`，可能命中一个「请求的路径并不指向」的文件——与 A1 同源，因此一并修正。

## 二、问题定位

### A1：长度参数为负的 `snprintf`

```cpp
    strcpy(m_real_file, doc_root);
    int len = strlen(doc_root);
    ...
    snprintf(m_real_file + len, FILENAME_LEN - len, "%s", m_url);
```

`m_real_file` 为 `char[FILENAME_LEN]`（200 字节）。当 `len > 200` 时，`FILENAME_LEN - len` 是**负的 `int`**，传入 `snprintf` 后按 `size_t` 解释为极大值——长度上限形同虚设，写入越过 `m_real_file` 的边界。

### A2：漏掉一行的 `strcpy`

```cpp
        strcpy(log_name, p + 1);     // log_name 为 char[128]
```

`003` 已给同一函数的 `dir_name` 拷贝加了长度限制，**`log_name` 这一行被漏掉**。此前 `log_name` 的来源恒为字面量 `"ServerLog"`，`011` 把它变成配置项后该路径才可达。

### 4.2：截断后的路径仍被 `stat`

即使不发生越界（`len ≤ 200`），拼接写不下时也会静默截断，而截断结果照样交给 `stat`。这使一个超长请求可能命中另一个已存在的文件。

## 三、设计方案

三条防线，从配置到请求逐层收窄：

| 层 | 做法 | 覆盖 |
|:--|:--|:--|
| 启动校验 | `root_dir`（`realpath` 之后）与日志文件名超长即终止启动，给出明确提示 | 只取决于配置的错误，在启动时一次性暴露 |
| 拼接有界 | 新增 `set_real_file`，以 `snprintf(m_real_file, sizeof(m_real_file), ...)` 一次成型并检查是否截断 | 请求路径本身超长 |
| 拷贝限长 | `log_name` 的拷贝补上与 `dir_name` 一致的边界检查 | 防御性的第二层 |

### 根目录上限的取值

```cpp
    static const int LONGEST_PAGE_PATH_LEN = 20; //"/Upload-Success.html"
    static const int MAX_ROOT_DIR_LEN = FILENAME_LEN - LONGEST_PAGE_PATH_LEN - 1;
```

取 179，依据是「固定页面的路径必须仍能拼进去」——`/Upload-Success.html` 是其中最长的一个（20 字节）。低于该上限时，所有内置页面都保证可访问；高于该上限则连内置页面都会拼不下，属于配置错误，因此放在启动阶段拒绝。

### 为什么是「拒绝」而不是「放宽缓冲区」

`m_real_file` 保持 200 字节不变。`http_conn` 按 `MAX_FD = 65536` 一次性分配数组，把该成员放大到 `PATH_MAX`（4096）会让常驻内存增加约 250 MiB，与「动态缓冲」方向（`013`）相悖。因此选择保留容量、把「装不下」显式化：

- 配置层面装不下 → 启动即拒绝
- 请求层面装不下 → `400 Bad Request`，而不是截断后错误命中

## 四、实现要点

| 文件 | 改动 |
|:--|:--|
| `http/http_conn.h` | 新增 `LONGEST_PAGE_PATH_LEN` 与 `MAX_ROOT_DIR_LEN`；声明 `set_real_file` |
| `http/http_conn.cpp` | 新增 `set_real_file`；`do_request` 中删除 `strcpy` + 偏移拼接，七处映射统一走 `set_real_file` 并判返回值；`serve_uploaded_file` 增加长度检查 |
| `log/log.h` | 新增 `LOG_NAME_SIZE`，`log_name` 的容量改由它定义，供启动校验引用 |
| `log/log.cpp` | `log_name` 的拷贝改为限长 `memcpy` + 手工结尾 |
| `webserver.cpp` | `init` 校验 `root_dir` 长度；`log_write` 校验日志文件名长度 |

### 顺带移除的一处死写入

`do_request` 的 cgi 分支里原本有一次 `snprintf`：

```cpp
        snprintf(m_real_file + len, FILENAME_LEN - len, "/%s", m_url + 2);
```

该写入的结果**从不被使用**：同一函数随后必然进入下面的映射分支，且注册/登录已把 `m_url` 改写为 `/log.html`、`/registerError.html` 一类的跳转页，因此那里用改写后的 `m_url` 覆盖了它。改为统一映射后，这行没有保留的理由，遂删除。

## 六、遗留问题

1. **`m_real_file` 的 200 字节仍是全局瓶颈**：根目录取到上限附近（如 170 字符）时，较长但仍合法的请求路径会得到 400。当前判断是「不为此扩大每个连接对象的固定开销」，若将来要支持深目录站点的长路径，应改为按请求动态持有路径
2. **启动校验只覆盖 `root_dir` 与日志文件名**：日志目录（`dir_name[128]`）超长仍会被静默截断到另一个目录，只是不会越界。是否一并拒绝，留待批次三一并看待
3. **`Expect: 100-continue`、长连接默认值、上传目录缺失等**：属批次二范围，本次未动
