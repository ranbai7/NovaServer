# 028 · 移除 `-a` 参数、线程数校验与 EMFILE 兜底验证

> 本记录是**阶段三的第五批（3.5）**，承接 `026` 第六节遗留的第 2 项。它处理三件事：并发模型参数已经失去意义、子线程数的取值缺乏校验、以及 `Acceptor::handle_fd_exhausted` 这段兜底代码写了却从未被构造出触发场景。

## 一、移除 `-a`（actor_model）

`-a` 是半同步/半反应堆时代的选择器：`0` 为 Proactor、`1` 为 Reactor。`025` 删除旧架构之后，服务端只剩 one loop per thread 一种形态，`Config::actor_model` 不再被 `WebServer` 读取，参数已经失去意义，但仍在命令行与配置文件里接受取值——保留了「改了参数却没有对应行为」的误导。

| 文件 | 改动 |
|:--|:--|
| `config.h` | 删除 `int actor_model;` |
| `config.cpp` | 删除默认值、`getopt` 取值串中的 `a:`、`case 'a'` 分支、`int_item("server", "actor_model", ...)` |
| `config.example.ini` | 删除 `actor_model` 行 |
| `README.md` | 命令行用法中删除 `[-a actor_model]` |
| `test_pressure/bench.sh` | 参数组合由 `-m -a -t` 三元组改为 `-m -t` 二元组 |

`config.ini` 是本地的未跟踪文件，同样删除了该行——配置文件里出现无法识别的键会终止启动，不删会导致服务端起不来。

### 附带：未知参数不再被静默忽略

`parse_arg` 的 `default` 分支原本只有 `break`，任何拼错的参数都被悄悄吞掉。移除 `-a` 之后这一点变得危险：`-a` 会落入 `default` 而被忽略，使用者会以为它仍然生效。因此改为报错并终止启动，与配置文件「无法识别的键终止启动」的处理保持一致。

```
$ ./build/server -a 0
./build/server: invalid option -- 'a'
无法识别的参数: -a
```

## 二、子 Reactor 线程数的校验

`EventLoopThreadPool::start()` 对 `m_thread_num <= 0` 一律不建线程。这使**负数与 0 产生了相同的效果**，而 0 是有意保留的取值（全部连接归主循环，用于与多线程分发对照，`026` 第三节）；负数则只会是笔误。二者混同会让「改了参数却没生效」看起来像是「多线程没有收益」。

因此在 `WebServer::init()` 中拦下负数，与既有的触发模式校验并列：

```
$ ./build/server -t -1
子 Reactor 线程数非法: -1（须不小于 0）
```

**0 保持合法**，`-t 0` 冒烟验证：服务只起 1 个线程（`/proc/<pid>/task` 计数为 1），`/judge.html` 返回 200。

## 三、`handle_fd_exhausted` 的验证

这段兜底自 `024` 起就存在，但一直没能构造出描述符耗尽的场景。验证方式是把服务端的 `RLIMIT_NOFILE` 降到 64（可用描述符约 50 个），用 Python 建立远多于该数量的连接占满描述符，再在**已耗尽的状态下**发起一次探测请求。

关键是对照：描述符充足时探测会拿到正常响应，耗尽时新连接会走到「建立即关闭」的路径。两者的差异才说明 EMFILE 分支确实被走到，而不是靠「没崩溃」推断。

| 阶段 | LT+LT（`-m 0`） | ET+ET（`-m 3`） |
|:--|:--|:--|
| 描述符充足时探测 | `HTTP/1.1 200 OK` | `HTTP/1.1 200 OK` |
| 占用 120 条连接后探测 | 连接被立即关闭 | 连接被立即关闭 |
| 服务端存活 | 是 | 是 |
| 占满的连接关闭后 | `/judge.html` 返回 200 | `/judge.html` 返回 200 |

两种触发模式下的行为一致：**耗尽不导致崩溃，兜底路径确实被走到，描述符释放后服务正常恢复**。ET 下的表现尤其值得确认——该模式下 EMFILE 不会再次触发事件，若无兜底，排在 accept 队列里的连接将无人处理。

复现命令：

```bash
( ulimit -n 64; exec ./build/server -p 9094 -m 3 -t 1 -c 1 ) &
python3 test_pressure/emfile_test.py 9094 120
```
