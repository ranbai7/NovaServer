## 四、代码问题

### 4.1 配置驱动的缓冲区溢出 → 崩溃（两处，已实测复现）

**A1：`root_dir` 过长导致每个请求崩溃**

- 位置：`http/http_conn.cpp` 的 `do_request`，`strcpy(m_real_file, doc_root)` 与 `snprintf(m_real_file + len, FILENAME_LEN - len, ...)`
- 根因：`m_real_file` 为 `char[200]`（`FILENAME_LEN`）。当 `len = strlen(doc_root) > 200` 时，长度参数 `FILENAME_LEN - len` 为负，传给 `snprintf` 后按 `size_t` 解释为极大值，写入越界地址
- 复现：`root_dir` 指向一个 267 字符的目录，请求任意页面 → Release 构建退出码 **134（核心已转储）**，ASan 报 `SEGV`
- 定性：该代码路径早于阶段二即存在（原先 `m_root` 由 `getcwd()` 推导，工作目录很深时同样触发），但 `011` 把根目录变成配置项后，触发条件从「几乎不可能」变为「配置写错即触发」，而当时只做了取值合法性校验、未做长度校验

**A2：日志文件名过长导致启动崩溃**

- 位置：`log/log.cpp` 的 `strcpy(log_name, p + 1)`，`log_name` 为 `char[128]`
- 复现：配置中日志文件名取 300 字符 → 启动即 ASan 报 `global-buffer-overflow ... in __interceptor_strcpy`
- 定性：`003` 已给同一函数的 `dir_name` 拷贝加了长度限制，**`log_name` 这一行被漏掉**；`011` 把日志文件名变成配置项后该路径才可达（此前恒为字面量 `"ServerLog"`）

### 4.2 `m_real_file` 静默截断会命中非预期文件

- 位置：`do_request` 中全部 `snprintf(m_real_file + len, FILENAME_LEN - len, ...)` 调用
- 现象：路径被截断后仍用于 `stat`，可能命中一个「请求的路径并不指向」的文件
- 复现：在 `root/` 放一个 157 字符的文件名，请求 `/<该名>XXXXXXXX...`（更长）→ **200 且返回该文件内容**
- 影响：当前 `root/` 无此类文件名，且攻击者无法在 `root/` 中创建文件，故暂不可被远程利用；但与 A1 同源，应一并修正

### 4.3 未实现 `Expect: 100-continue`

- 现象：curl 等客户端对大于 1 KB 的 POST 默认发送 `Expect: 100-continue`，服务端既不回 `100 Continue` 也不拒绝，客户端只能等自身的期望超时
- 复现：同一上传，`curl -F` 默认 **1.04 s**，加 `-H 'Expect:'` 后 **0.036 s**——即所有大体积上传固定多付约 1 秒
- 相关：该头当前被当作未知头部记录（`oop!unknow header: Expect`）

### 4.4 HTTP/1.1 默认长连接未实现（既有，非阶段二引入）

- 位置：`parse_headers` 中仅当客户端显式发送 `Connection: keep-alive` 时才置 `m_linger = true`
- 现象：不带该头时服务端在首个响应后关闭，而 HTTP/1.1 的默认语义是保持连接
- 复现：显式 keep-alive → 同一连接上 2 个请求均成功；不带 → 第 2 个请求 `Broken pipe`
- 定性：已用 `git show` 比对最初提交，该逻辑逐字节相同，属既有问题

### 4.5 上传目录缺失时列表页返回 500

- 位置：`build_upload_list` 中 `opendir` 失败即返回 `INTERNAL_ERROR`
- 复现：将 `upload/` 移走后 `GET /upload` → **500**
- 期望：视为空列表（或按需创建目录），而不是服务端错误

### 4.6 隐藏文件名在上传与列表之间规则不一致

- 现象：上传 `.audit-hidden.txt` → 200 且落盘，但列表页跳过点号开头的文件，导致文件存在却不可见
- 位置：上传侧无文件名限制（仅拒绝 `/`），列表侧跳过 `name[0] == '.'`

### 4.7 清理项

| 项 | 位置/说明 |
|:--|:--|
| 死成员 | `sql_user` / `sql_passwd` / `sql_name`（写入但从不读取）、`m_users`（从未使用） |
| 注释代码块 | `process_write` 中约 40 行注释掉的 `UPLOAD_SUCCESS` 分支 |
| 负偏移指针运算 | `write()` 中 HEAD 截断头部后 `m_file_address + (bytes_have_send - m_write_idx)` 为负（此时指针为空且未被解引用，属未定义行为） |
| 拒绝时机偏晚 | 扩展名不符（415）在读完整具请求体之后才返回 |
| 内存放大 | `parse_multipart_content` 先整体拷贝请求体（≤8 MiB）再取出文件内容（≤4 MiB），单次上传峰值约 12 MiB |
| 返回值未检查 | `process_write` 中多处 `add_status_line` / `add_content_type` 未判返回值，写缓冲触顶时会产生半截响应且仍返回成功 |

## 六、修复计划

按严重度分四批，每批单独提交。

### 批次一 · 崩溃修复（A1、A2、4.2）

1. 启动时校验 `root_dir` 与日志文件名的长度上限，超限即终止启动并给出明确提示（与既有的「根目录不存在」校验放在同一处）
2. `do_request` 与 `serve_uploaded_file` 中的 `m_real_file` 拼接改为有界：统一以 `snprintf(m_real_file, sizeof(m_real_file), ...)` 一次成型，并检查是否发生截断；截断即判为错误请求，不再用于 `stat`
3. `log.cpp` 中 `log_name` 的拷贝恢复边界检查（与同函数 `dir_name` 的处理保持一致）

### 批次二 · 协议与行为补齐（4.3、4.4、4.5、4.6）

4. `Expect: 100-continue`：在读完请求头后、等待请求体前回应 `100 Continue`（或直接给出最终状态码）
5. HTTP/1.1 默认长连接：`m_linger` 默认置真，仅在显式 `Connection: close` 时为假（HTTP/1.0 保持默认关闭）
6. `build_upload_list`：目录不存在时返回空列表而非 500
7. 统一隐藏文件的处理：上传侧拒绝点号开头的文件名，或列表侧纳入展示（二者取一，需明确取舍）

### 批次三 · 清理（4.7）

8. 删除死成员与注释代码块；`write()` 中避免负偏移的指针运算；扩展名校验提前到可判定时；评估上传路径的内存放大；补检查 `add_status_line` 等的返回值；修正日志文案
