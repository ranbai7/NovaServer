# 030 · 日志双缓冲批量落盘

> 阶段四的第一批。本次改造把日志的落盘单位从「一行」变为「一整块」，写入路径上不再
> 逐行产生系统调用，文件轮转也移出调用线程。过程中修掉三处既有缺陷，并在验证中
> 发现实现自身的一处缺陷与一处工具误报，一并记录。

## 一、背景与动机

日志在请求路径上被大量调用。以静态页面请求为例，**单次请求会产生约 23 行日志**：
`process_read` 每解析一行请求行或请求头记一条，`add_response` 每次向写缓冲追加内容
也记一条。这些调用点落在子 Reactor 线程上，而旧实现把它们全部串行化到同一把锁与
同一个文件指针上。

旧实现每写一行的代价：

- `LOG_*` 宏每行都会调一次 `flush()`，即**每行一次 `fflush`**
- `write_log` 每行取锁三次（轮转判断、格式化到共享缓冲、写文件），异步路径还有
  阻塞队列的 `full()` 与 `push()` 各一次锁加一次 `broadcast`
- 文件轮转（`fclose` + `fopen`）也在调用线程、持锁进行

## 二、现状分析

### 改造前实测（开启日志）

`-m 0`，100 并发，5 秒，5 次取中位数，详见第四节。要点：

| 组 | -t 2 | -t 8 |
|:--|--:|--:|
| 同步（`write_mode = 0`） | 15792 | 17403 |
| 异步（`queue_size = 800`） | **9157** | 24523 |
| 异步（`queue_size = 10`） | 8221 | 18958 |

作为对照，同一环境下关闭日志的吞吐在 25k 上下。也就是说**开启日志要付出约四成吞吐**，
而旧的异步方式在 `-t 2` 下甚至比同步更慢——它的队列与锁的开销超过了它省下的写调用。

### 三处既有缺陷

改造中的参数夹取顺带修掉了三处缺陷，它们都由**配置取值**触发，现有测试从未覆盖：

| 缺陷 | 表现 | 证据 |
|:--|:--|:--|
| `log.cpp` 的 `snprintf(m_buf, 48, ...)` | 缓冲区只有 `buf_size` 字节，而时间前缀固定按 48 字节写入；`buf_size < 48` 时是**堆越界写** | ASan 在 `buf_size = 16` 下报 `heap-buffer-overflow`，写入 36 字节到 16 字节的堆块，栈顶正是该行 |
| 同一处的算术 | `n` 与前后的长度参数都基于 `m_log_buf_size` 作差，取值过小时 `n` 会变成负值，`m_buf + n` 与长度参数一并下溢 | 与上一条同源；ASan 下先被上一条中断，故一并按「配置无校验」处理 |
| `init` 重复调用不 `fclose` | 每次 `init` 都重新 `fopen`，上一份文件句柄泄漏 | 单测 `RepeatedInitDoesNotLeakFd` 直接以 `/proc/self/fd` 的条目数核对 |

修法是给这几项配置定下合法区间，越界时启动阶段直接报错（与触发模式、线程数一致），
`Log::init` 内部再夹一次作为兜底。

## 三、设计方案

### 为什么是缓冲池而不是「两块缓冲」

常见写法是 front / back 两块。但块写满之后要么丢弃、要么排队，一旦排队就需要一个
空闲块的来源，池化是必然结果；此时「备用块」已经等同于「空闲栈里的任意一块」，
再单列一个 `m_back` 只会引入需要额外推理的状态。因此采用三个角色：

| 角色 | 说明 |
|:--|:--|
| `m_front` | 当前写入块 |
| `m_pending` | 已写满、等待落盘，先进先出。**有且只有写盘线程会取走它**，文件内容的顺序因此等于写入顺序 |
| `m_free` | 空闲块 |

池大小固定为 9 块（1 块当前写入 + 8 块可排队），内存上界即 `9 × batch_buf_size`。
池在 `init` 时一次性分配，三个指针数组一并预留容量，此后写入与落盘路径都不再分配。

### 写入路径

1. 取时间（`localtime_r`）
2. 把时间前缀与内容格式化进**线程私有的定长缓冲**
3. 取一次锁，`memcpy` 进 `m_front`；放不下就换块并唤醒写盘线程

值得说清的是第 2 步为何用编译期定长的数组而不是按配置扩容的容器：容量若取决于运行期
配置，第 2 步就得无锁读一个会被 `init` 改写的量（数据竞争），或者为它加锁——两条路
都堵死。把 `buf_size` 夹到 `[128, 4096]` 并固定数组容量，问题就不存在了。

措辞也要准确：写入路径**没有系统调用、没有内存分配**，但并非零成本——取时间、格式化
仍在，且换块时那次唤醒通常是一次 futex。唤醒只在换块时做，逐行唤醒会把刚省下的系统
调用又按行加回来。

### 落盘、轮转与背压

写盘线程在「缓冲块写满」或「到达 `flush_interval`」时醒来，把 `m_pending` 整体取出，
**在锁外**整块 `fwrite`。轮转（按天、按行数）也在这里做，位于排空之后以保证顺序。

背压的判据取「池中没有空闲块」，与「待写队列超长」等价，但直接对应真正要约束的内存。
触发时丢弃新行并计数，由写盘线程在下一次落盘时写成一行「已丢弃 N 行日志」——
丢失在文件里可见，而不是无声无息。这里**不同步写盘**：旧的异步实现在队列满时由调用
线程直接落盘，把一次磁盘写压在 Reactor 线程上，正是这次要消除的东西。

### 同步方式为何不做缓冲

同步方式的语义是「写入即落盘」。若让它也走缓冲池，多个 Reactor 线程各自排空时会
出现「取块」与「写文件」之间的窗口，块的落盘顺序可能与写入顺序相反。改为每行直接
写文件、由同一把文件锁串行化，顺序即取得锁的顺序——与原实现一致，也最简单。

因此两种方式的差别收敛为一句话：**写盘线程在不在**。运行期的分支判断依据是
`m_writer_active` 而不是配置项，同步方式便不再有第二处语义。

### 其它取舍

| 取舍 | 决定 | 理由 |
|:--|:--|:--|
| `init` 的参数 | 改用具名字段的结构体 `LogConfig` | 这些取值里有五个是 int，相邻两个写反编译器不报错，运行期只表现为「某个配置没生效」 |
| `split_lines` | 改为**软**上限 | 判据是「整块写下去会不会越过」，文件可能多出不到一块的行数；换来写盘侧永远只做整块写出，不必按行切分或维护行偏移表 |
| 日切判据 | 取年、月、日三者，且按**块内首行**的时刻 | 旧实现只比 `tm_mday`，跨月同日（8-05 到 9-05）不会切分 |
| `LOG_ERROR` | 保留一次 `flush()` | 错误行是排障时最不能丢的信息，而按间隔批量落盘意味着崩溃时最多丢一个间隔 |
| `block_queue.h` | 删除 | 新设计不再使用，而生产代码中它的唯一使用者就是 `Log`；`lock/locker.h` 不受影响，仍被连接池与用户表使用 |
| 配置项 | 删除 `[log] queue_size`，新增 `batch_buf_size` 与 `flush_interval` | **破坏性变更**：`Config` 对无法识别的键硬报错，沿用旧配置会启动失败并明确提示 |

## 四、实现要点

| 文件 | 改动 |
|:--|:--|
| `log/log.h` | `LogConfig`；缓冲池、两把锁与两个条件变量；`LOG_DEBUG/INFO/WARN` 去掉逐行 `flush()`，`LOG_ERROR` 保留；宏改 `do-while` 包裹 |
| `log/log.cpp` | `init` / `write_log` / `flush` 重写；新增 `writer_loop`、`drain_locked`、`retire_front_locked`、`write_batch`、`write_line_direct`、`rotate_if_needed_locked` |
| `webserver.{h,cpp}` | 组装 `LogConfig`；新增配置取值范围校验；析构末尾（子线程已 join 之后）排空日志 |
| `config.{h,cpp}`、两份 ini | 键替换；`write_mode` 默认改为 1；`buf_size` 与 `split_lines` 的注释更正 |
| `tests/test_log.cpp` | 由 2 例扩到 12 例；`tests/CMakeLists.txt` 删除 `test_block_queue.cpp`，并给 `log_tests` 加超时 |
| `log/README.md`、`docs/architecture.md`、`README.md` | 同步更新 |

两把锁的用法：`m_mutex` 保护缓冲池，`m_file_mutex` 保护文件位置，**从不同时持有**。
后者的意义是把「同一时刻只有一个写文件的人」变成结构约束而不是约定——两种写入方式
都经 `write_batch` 进这把锁，将来即便出现第三种排空者也不会写坏文件。

`flush()` 的完成判定用「已落盘的最后一块序号」；该序号必须在**取走待写队列的同一个
临界区内**捕获，取排空结束时的值会把期间新入队的块误报为已落盘。池满时 `retire` 会
失败，因此 `flush()` 在池满时等待写盘线程腾出块后重试，而不是等一次就返回。

## 五、验证

### 5.1 改造前后对比（开启日志）

同一环境、同一时段，`-m 0`，100 并发，5 秒一组取中位数。服务端以 `-c 0` 打开日志，
其余与阶段零的方法一致（改动前的三组在改造开始前采集，改动后旧实现不可复原）。

| 写入方式 | 改动前 -t 2 | 改动后 -t 2 | 改动前 -t 8 | 改动后 -t 8 |
|:--|--:|--:|--:|--:|
| 同步 | 15792 | 14496 | 17403 | 16789 |
| 异步 | **9157** | **36209** | 24523 | 24053 |

- **异步 -t 2 提升约 4.0 倍**（9157 → 36209，9 次重复的区间为 28125~39216），
  P50 从 10.690ms 降到 2.620ms，P99 从 22.410ms 降到 5.790ms
- **同步基本持平**（-8%，落在阶段零记录的 ±10% 噪声内）——符合预期，它按设计仍是每行
  一次写入
- **异步 -t 8 与改动前持平且方差很大**（20766~28101），且明显低于 -t 2。并发 8 个子
  Reactor 加写盘线程共 10 个线程跑在 4 个逻辑核上，超过核数之后日志的互斥量成为争用点。
  这本身是这次改造带来的一个可观测事实：**批量落盘下线程数并非越多越好**

改造前后的**每请求日志行数**一致（改动前 1145855 行 / 49521 次请求 = 23.1，
改动后 1009327 行 / 43509 次请求 = 23.2），说明调用点的行为未因改造而变化——
这是本次改动最该守住的性质。逐行内容的正确性由单元测试的顺序与完整性断言保证。

### 5.2 每行日志的成本

`-t 2`，3 秒，读 `/proc/<pid>/io` 的写系统调用增量与 `/proc/<pid>/stat` 的 CPU 时间：

| 组 | QPS | 每行写调用 | 每行 CPU tick |
|:--|--:|--:|--:|
| 改动前 · 同步 | 16507 | 0.385 | 0.00041 |
| 改动前 · 异步（队列 800） | 9375 | 0.195 | 0.00072 |
| 改动前 · 异步（队列 10） | 8188 | 0.247 | 0.00080 |
| 改动后 · 同步 | 14503 | 0.392 | 0.00048 |
| 改动后 · 异步 | **36632** | **0.045** | **0.00023** |

每行日志的写系统调用降到约 **1/4.3**，CPU 时间降到约 **1/3.1**。同步方式的每行成本
与改动前一致，印证收益全部来自「不再逐行落盘」。

（写调用数并非按行计一次：stdio 自身会缓冲，旧实现的 0.385 已是若干行合成一次写出去的
结果。改造后由本模块的缓冲池决定落盘时机，整块写出，于是降到每块一次。）

### 5.3 单元测试

`tests/test_log.cpp` 由 2 例扩到 12 例，覆盖缓冲边界、行数与顺序、排空语义、定时刷新、
轮转、重复 init 与背压记账：

| 用例 | 判据 |
|:--|:--|
| `LineNeverExceedsBufferSize` | 行长不超过单行上限；**ASan 下不报越界**——这类越界不改变可观测输出，只能靠 ASan |
| `OutOfRangeBufferSizeIsClamped` | 配置给 16 时被夹到下限，不再越界写 |
| `ShortMessageIsWrittenIntact` | 短消息不被裁剪 |
| `FlushMakesEverythingDurable` | `flush()` 返回后此前写入的行全部可见 |
| `AsyncFlushesOnIntervalWithoutExplicitFlush` | **不调用 `flush()`**，写盘线程按间隔自行落盘 |
| `AsyncDoesNotWriteBeforeFlush` | 间隔远大于用例时长且只写一行（远小于一块）时，文件仍为空——批量而非逐行 |
| `SyncWritesImmediately` | 同步方式不调用 `flush()` 也立即可见 |
| `ConcurrentLinesAreIntactAndOrdered` | 4 线程 × 2000 行：行数相符、每行完整可匹配、同一线程自身序号严格递增 |
| `NoLineLostWhileProducingAndFlushing` | 边写边排空时逐轮核对屏障，最终核对「普通行 + 丢弃 = 写入」 |
| `RepeatedInitDoesNotLeakFd` | 20 次 `init` 后 `/proc/self/fd` 条目数不增长 |
| `RotationPreservesOrder` | 各后缀文件按序拼接后，行序列与写入序列完全一致 |
| `BackpressureAccountIsBalanced` | 构造必然触发丢弃的负载，核对守恒式，并确认丢弃路径确实被走到 |

三套构建下的结果：

| 构建 | 结果 |
|:--|:--|
| Release | 7/7 目标通过 |
| AddressSanitizer | 7/7 目标通过，无报告 |
| ThreadSanitizer | 12 个日志用例全部通过（报告见 5.5，均为工具误报） |

轮转、背压、并发这三条都用探针确认过**路径确实被走到**——例如轮转用例实际切出了
11 个文件；背压用例最初参数不足以触发丢弃，调整到「单行取上限、块取最小值」（此时
一个块只装得下一行，9 块很快填满）后三次探测的丢弃率均在 92% 上下。

### 5.4 功能链路

新增 `test_pressure/smoke.sh`，覆盖静态资源、站点根、404、URL 转义、HEAD 与
`Content-Length`、路径穿越、上传白名单与取回闭环、空闲连接回收，共 13 项，全部通过。
上传后能通过 `/upload/<名称>` 取回且内容一致；空闲连接在 17 秒内被回收且服务端仍存活。

**验证中发现一个既有崩溃**：登录与注册会把一个从未从连接池取过的空 `MYSQL*` 交给

### 5.5 ThreadSanitizer 的误报

TSan 在日志模块报出 31 条数据竞争与 1 条重复加锁，覆盖 `m_mutex` 保护下的几乎每一处
访问。判据是：**同一互斥量保护下的两处访问被报成竞争**——这本身不自洽，说明工具记错了
锁的归属。

写一个**不含任何 `Log` 代码**的最小程序（`mutex` + `condition_variable` + 写线程），
逐一替换等待写法，结果：

| 等待写法 | TSan 报告数 |
|:--|--:|
| `wait_for` 带谓词 | 3 |
| `wait_for` 不带谓词 | 3 |
| `wait_until`（steady_clock） | 3 |
| `pthread_cond_clockwait` | 3 |
| `wait` 带谓词（**无超时**） | **0** |
| 解锁 + `sleep_for` + 加锁 | **0** |

再把 `writer_loop` 里那一处定时等待临时换成轮询（语义等价、仅用于实验），日志测试的
**报告数归零，12 个用例仍全过**，而实现本身不变。

结论：**本工具链（GCC 11 的 libstdc++ 与 libtsan）在处理带超时的条件变量等待时会把
互斥量的持有状态记错**，凡是该互斥量保护下的访问都会被报出来；与本模块的实现无关。
考虑到轮询会引入真实的落盘延迟与更多丢弃，**保留 `wait_for`**，并在 `log.cpp` 与
`docs/architecture.md` 留下指引，避免后来者去追这个幽灵。

### 5.6 验证中发现的实现缺陷

改造后的第一版里，写盘线程醒来只排空 `m_pending`（已写满的块），**没有处理 `m_front`
里未满的那一块**。而定时刷新的意义恰恰是「块没满但已经等够久了也要落盘」。后果是
异步方式下日志长期留在内存：冒烟测试里跑了三次请求、等过一个刷新间隔，文件仍是空的；
只有恰好写满一块或进程退出才会落盘。

更值得记的是**测试为什么没发现它**：当时那条用例断言的是「未调用 `flush()` 时文件应为空」，
它把错误行为当成了正确断言，于是通过了。补上的
`AsyncFlushesOnIntervalWithoutExplicitFlush` 才是对的判据——不调用 `flush()`，
按间隔等待后内容必须可见。该用例在去掉修正后立即失败，确认有效。

## 六、遗留问题

1. **登录与注册的崩溃**（既有缺陷，与本次改造无关）。修复需要让 `http_conn` 能够取得
   连接池——可沿 `WebServer → TcpConnection → http_conn::init` 已有的参数通路传入，
   与该路径上现有的 `root_dir`、`close_log` 一致。作为紧随其后的一批处理。
2. **TSan 的工具误报**（见 5.5）。日志模块的 TSan 报告需按上述判据甄别；这是工具限制，
   无法在本项目内消除。
3. **`split_lines` 由精确上限变为软上限**（见第三节）。如需文件行数严格不超过该值，
   需要按行切块或维护行偏移表，代价与收益不成比例。
4. **崩溃时最多丢一个 `flush_interval` 的日志**。这是批量落盘的固有代价；`flush_interval`
   默认 1 秒，可按需调小。优雅退出（`SIGTERM`）仍完整落盘。
5. 阶段四剩余两项：按阶段零方法重跑压测并与 `021` 基线对照、AddressSanitizer 的服务端
   全链路运行（单元测试与功能链路已过 ASan）。
