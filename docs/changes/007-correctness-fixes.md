# 007 · 连接处理与日志路径的确定性缺陷修正

## 一、背景与动机

阶段一收尾时留下了三项确认但未处理的缺陷（见 `003-warning-cleanup.md` 的遗留问题），路线图的阶段二又列出了若干同类的正确性问题。这些缺陷有几个共同特征：

- **不影响正常路径的返回结果**，因此功能测试很难发现
- **不改变核心数据结构与线程模型**，可以独立于阶段三的并发重构先行处理
- 其中一部分依赖运行时数据，静态分析与代码审查都容易漏过

因此阶段二从这一组开始：先把「已经明确错了」的地方改对，为后续协议层的改动留出一个干净的基础。

本次处理五项：

| 项 | 缺陷性质 |
|:--|:--|
| 触发模式配置 | 成员赋值晚于使用，参数完全失效 |
| 读取返回值 | 负数直接累加读索引，破坏缓冲区游标 |
| 成员未初始化 | 悬垂指针、判空逻辑失效 |
| 日志缓冲区边界 | 越界写 |
| 共享用户表同步 | 读写同步策略不对称 |

## 二、现状分析

### 触发模式实际从未生效（路线图问题 1）

`http_conn::init` 中原顺序为：

```cpp
addfd(m_epollfd, sockfd, true, m_TRIGMode);   // 使用 m_TRIGMode
m_user_count++;
doc_root = root;
m_TRIGMode = TRIGMode;                        // 此时才赋值
```

`addfd` 依据 `m_TRIGMode` 决定是否给连接套接字打上 `EPOLLET`，而读取发生在赋值之前——读到的是成员变量的未初始化取值。构造函数 `http_conn() {}` 也未初始化该成员，因此这里读取未初始化值属于未定义行为。

后果是 `-m 1`（LT+ET）与 `-m 3`（ET+ET）中连接侧的 ET 从未真正注册，而 `-m 2`（ET+LT）只影响监听套接字。基线记录里「`-m 0` 与 `-m 1` 的差异落在噪声区间内」正是这一缺陷的表现。

### 读取返回值为负时污染读索引

LT 分支：

```cpp
bytes_read = recv(m_sockfd, m_read_buf + m_read_idx, READ_BUFFER_SIZE - m_read_idx, 0);
m_read_idx += bytes_read;          // 先累加
if (bytes_read <= 0) return false; // 后判断
```

套接字已设为非阻塞，`recv` 可能返回 `-1`。此时 `m_read_idx` 被减 1，游标指向错误的字节；即便随后关闭连接，`m_read_idx` 也已损坏。ET 分支则已经区分了 `EAGAIN`、其他负值与 0 三种情况，两个分支的处理并不一致。

### 请求体与文件映射指针未复位

`init()` 重置了 `m_url`、`m_version`、`m_host` 等成员，但遗漏了 `m_string`（指向请求体）与 `m_file_address`（`mmap` 的返回值）：

- `unmap()` 以 `if (m_file_address)` 判断是否需要解除映射。连接对象会被复用，若上一次请求映射过文件而指针未清空，下一次 `unmap()` 可能对已失效的地址调用 `munmap`
- `m_string` 为空时，`do_request` 中的 CGI 分支会按固定偏移读取请求体（`m_string[i]`）

### 日志缓冲区越界写（路线图问题 8）

```cpp
int n = snprintf(m_buf, 48, "<时间戳与前缀> ...");
int m = vsnprintf(m_buf + n, m_log_buf_size - n - 1, format, valst);
m_buf[n + m] = '\n';
m_buf[n + m + 1] = '\0';
```

`vsnprintf` **在截断时返回的是「本该写入的长度」而非实际写入长度**。当格式化结果长于剩余空间时，`n + m` 会超出 `m_buf` 的分配大小，随后的换行与终止符就写到了缓冲区之外。

这个越界的隐蔽之处在于**它不改变任何可观测的输出**：`vsnprintf` 已在截断处写好终止符，多出来的两个字节落在终止符之后，日志字符串本身始终是短的。因此单纯的输出断言无法区分修复前后（详见验证一节）。

### 共享用户表同步不对称（路线图问题 11）

用户表 `users` 是文件作用域的 `std::map`，被多个工作线程并发访问，但：

| 访问点 | 同步情况 |
|:--|:--|
| `initmysql_result` 加载全表 | 无锁 |
| 注册时判重 | 无锁 |
| 注册时插入 | 加锁 |
| 登录时查询比对 | 无锁 |

只有一处加锁，其余读写都是裸访问。除数据竞争外，判重（无锁）与插入（加锁）分处两个临界区，两者之间存在竞态窗口，同一用户名可能被并发注册两次；而插入发生在锁内、却**无视数据库写入是否成功**，即使写库失败也会更新内存中的用户表，造成内存与数据库不一致。

### 顺带发现的两处泄漏

在 AddressSanitizer 下运行全链路时报告了两处确定的泄漏，均位于本次改动的代码附近：

- `WebServer` 构造函数用 `malloc` 生成根目录路径 `m_root`，析构函数未释放
- `initmysql_result` 取出的结果集从未 `mysql_free_result`，泄漏 152 字节并派生 8000 余字节

## 三、设计方案

### 触发模式：调整顺序，而非额外记录配置

备选方案是在 `init()` 中把 `TRIGMode` 作为参数层层传递到 `addfd`。但 `m_TRIGMode` 在连接的整个生命周期中都会被 `addfd` / `modfd` 反复使用（`process()`、`write()` 都在读它），成员变量本身是必要的。真正的错误只是**赋值时机**，因此只把赋值语句前移到注册之前，不引入新状态。

### 读取返回值：先判断，再累加

```cpp
if (bytes_read < 0)
    return (errno == EAGAIN || errno == EWOULDBLOCK);
if (bytes_read == 0)
    return false;
m_read_idx += bytes_read;
```

三种返回值分别对应三种语义：`EAGAIN` 是「此刻无数据」而非错误，连接仍然有效，返回 `true` 让调用方保留连接；其他负值是读取出错；0 是对端关闭。

LT 模式下返回 `true` 不会造成忙等：`recv` 返回 `EAGAIN` 意味着套接字当前不可读，LT 也就不会重复上报该事件。

### 成员初始化：统一在 `init()` 中复位

`init()` 是连接复用的唯一入口（`write()` 完成后的 keep-alive 复用也走这里），把 `m_string`、`m_file_address` 与 `m_iv_count` 一并复位即可覆盖所有复用路径。同时在 CGI 分支入口对 `m_string` 判空——POST 未携带请求体时解析无从进行，应直接判为错误请求。

### 日志缓冲：按实际可写长度裁剪

分别对前缀长度与格式化长度做上界裁剪，保证 `n + m + 1` 始终小于缓冲区大小：

```cpp
if (n > m_log_buf_size - 2) n = m_log_buf_size - 2;
int m = vsnprintf(m_buf + n, m_log_buf_size - n - 1, format, valst);
if (m > m_log_buf_size - n - 2) m = m_log_buf_size - n - 2;
```

关键是把 `vsnprintf` 的返回值视为「并非已写入长度」，在用它定位结尾前先裁剪到真实容量。裁剪后内容被截断而非丢弃，超长消息仍保留前若干字节，行为与原有「截断」语义一致。

### 用户表：把访问收敛到加锁封装

新增两个文件内函数，所有对 `users` 的访问只能经由它们：

| 函数 | 职责 |
|:--|:--|
| `lookup_user` | 查询口令，加锁 |
| `register_user` | 在**同一临界区内**完成「查重 → 写库 → 更新内存」，加锁 |

把「查重 + 插入」合并进一个临界区，消除了原先判重与插入之间的竞态；同时把内存表的更新条件改为「数据库写入成功」，恢复两者的一致性。

### 泄漏：显式释放

`m_root` 由 `malloc` 分配，在析构中 `free`；结果集在使用完毕后 `mysql_free_result`，并补充 `mysql_store_result` 的返回值判空——原实现在查询失败时会拿 `NULL` 去 `mysql_fetch_row`。

## 四、实现要点

| 文件 | 改动 |
|:--|:--|
| `http/http_conn.cpp` | `init(sockfd, ...)` 调整赋值与 `addfd` 的先后顺序；`init()` 复位 `m_string`/`m_file_address`/`m_iv_count`；`read_once()` LT 分支重排返回值判断；新增 `lookup_user`/`register_user` 并改写注册与登录路径；`initmysql_result` 加锁、补错误处理、释放结果集 |
| `log/log.cpp` | `write_log` 裁剪 `snprintf`/`vsnprintf` 的返回值；构造函数初始化指针成员；析构函数释放 `m_buf` 与队列；`init` 支持重复调用 |
| `webserver.cpp` | 析构函数释放 `m_root` |
| `tests/test_log.cpp`（新增） | 日志缓冲区边界的回归用例 |
| `tests/CMakeLists.txt` | 提取 `add_unit_test` 函数；把 Sanitizer 开关传递到测试目标 |
| `.gitignore` | 追加 `build-*/`，容纳 Sanitizer 构建目录 |

另外，`init(sockfd, ...)` 中三处写数据库连接信息的 `strcpy` 改为 `snprintf`——目标缓冲区固定 100 字节而源串来自配置，同样属于无长度约束的复制。

### 关于测试目标的 Sanitizer 开关

日志越界无法通过输出断言发现，只能靠 AddressSanitizer。但原先 `ENABLE_ASAN` 只作用于 `server` 目标，测试目标并不会带上该选项——即使按 `-DENABLE_ASAN=ON` 构建，单元测试仍是在无检查的情况下运行。本次把开关一并传到测试目标，使这类「只在 Sanitizer 下可见」的缺陷能够在单元测试层面被捕获，而不必每次都依赖手工的全链路运行。

## 五、验证

### 编译与格式

| 项 | 结果 |
|:--|:--|
| Release / Debug 构建 | 0 错误、0 警告 |
| `clang-format --dry-run --Werror`（23.1.1） | 改动文件无差异 |
| `ctest` | 2/2 通过 |

### 触发模式：以 `strace` 直接观察注册标志

修复效果无法从响应内容看出，因此用 `strace -f -e trace=epoll_ctl` 记录 `epoll_ctl` 的调用参数，直接查看连接套接字（`fd=15`，前两个 `ADD` 分别是监听套接字与 `socketpair`）的注册事件：

| 版本 | `-m 1`（LT+ET）connfd 注册事件 |
|:--|:--|
| 修复前 | `EPOLLIN\|EPOLLRDHUP\|EPOLLONESHOT` |
| 修复后 | `EPOLLIN\|EPOLLRDHUP\|EPOLLONESHOT\|EPOLLET` |

`-m 3` 在修复前后都带 `EPOLLET`（其监听侧为 ET，掩盖了连接侧的缺失），`-m 0` / `-m 2` 的连接侧本就不应带 ET。修复后四种组合的连接侧触发模式与 `-m` 参数的含义一致。

> 影响：连接侧的 ET 路径此前从未执行过，本次修复后它首次真正生效，其稳定性需要在阶段四重新压测确认。

### 日志越界：Sanitizer 下运行单元测试

`tests/test_log.cpp` 用远超缓冲区长度的消息触发截断。如「现状分析」所述，该用例的断言无法单独发现越界——因此以 `-DENABLE_ASAN=ON` 构建后运行：

| 版本 | 结果 |
|:--|:--|
| 修复前 | `ERROR: AddressSanitizer: heap-buffer-overflow`，`WRITE of size 1`，定位到 `log.cpp:142` |
| 修复后 | 2 个用例全部通过，无报告 |

修复前被还原为原始实现后运行以确认用例确实具备检出能力。`log.cpp:142` 即 `m_buf[n + m] = '\n';`。

### 功能冒烟：4 触发模式 × 2 并发模型

以脚本覆盖首界面、`/0`~`/8` 各触发路由、静态图片、登录（正确口令 / 错误口令 / 用户不存在）、注册（新用户 / 重名被拒）、上传（响应页 + 落盘校验），每个组合 16 项断言：

| 组合 | 结果 |
|:--|:--|
| `-m 0 -a 0`、`-m 1 -a 0`、`-m 2 -a 0`、`-m 3 -a 0` | 全部通过 |
| `-m 0 -a 1`、`-m 3 -a 1` | 全部通过 |

服务端进程在整个过程中无异常输出。修复前 `-m 1` / `-m 3` 的连接侧实际按 LT 运行，本次是这些组合的 ET 路径第一次被完整走通。

### AddressSanitizer 全链路

以 `-m 3 -a 1` 启动 Debug + ASan 构建，跑完整冒烟流程后以 `SIGTERM` 正常退出，使泄漏检查得以执行：

| 版本 | 结果 |
|:--|:--|
| 修复前 | `9930 byte(s) leaked in 21 allocation(s)`，两处直接泄漏（`m_root` 42 字节、结果集 152 字节）及其派生 |
| 修复后 | 无任何报告 |

### 用户表同步

该改动无法以单元测试隔离验证（封装位于 `http_conn.cpp` 内部），验证方式为：并发冒烟流程中注册与登录的不同时序均返回预期结果，且在 ASan（含泄漏检查）下运行无异常。竞态窗口本身已由「判重与插入合并进同一临界区」在结构上消除，而非依赖时序。

## 六、遗留问题

1. **日志初始化失败未被处理**：`webserver.cpp` 中 `Log::init` 的返回值被忽略。若日志文件打开失败（例如工作目录不可写），`m_fp` 将保持为空，后续 `write_log` 以空文件指针调用 `fputs`。另需注意日志文件名实际落在**当前工作目录**而非 `./ServerLog/`——`init` 中的 `dir_name` 只截取到最后一个 `/`，路径中的目录名被当作文件名处理。两项一并归入后续的日志相关改动
2. **注册路径被串行化**：`register_user` 在锁内执行 `mysql_query`，同一时刻只能有一个注册请求进入数据库。在当前规模下可接受；若需并发，应改为「库侧唯一约束 + 冲突重试」，把判重交给数据库
3. **参数解析仍依赖固定偏移**：登录与注册按 `user=` / `password=` 的固定下标提取字段，字段顺序、名称或缺失都会导致解析错误，归入下一项「参数解析健壮化」
4. **固定读缓冲区未改**：`m_read_idx` 达到 2048 后 `read_once` 直接返回失败并关闭连接，大请求体仍不可用，属阶段二的「动态缓冲改造」
5. **口令仍为明文**：本次只统一了同步策略，未改动存储形式
