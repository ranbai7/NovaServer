# NovaServer 项目解读

> 这套资料回答两个问题：**这个服务器是怎么做出来的**，以及**它在做出来的过程中为什么这样改**。
>
> 它从「浏览器按下回车之后发生了什么」讲起，先让你看懂一个 Web 服务器的最小工作方式，再逐项拆开本项目：静态页面怎么返回、注册登录怎么查库、文件怎么上传和下载、日志怎么写、多个连接怎么被高效处理。每一项功能讲清之后，再讲这一项在压力、正确性或性能上暴露了什么问题，以及本项目如何解决。

---

## 这套资料适合谁

假设你会写 C++，用过 Linux 命令行，但**没有系统学过服务器编程**：

- 不知道 socket、文件描述符、`epoll` 是什么；
- 听说过 Reactor、线程池，但说不清它们解决什么问题；
- 能看懂零散代码，但无法把「一个请求从浏览器到服务器再回来」串起来。

服务器领域的关键概念都会在**第一次出现时就地解释**，不要求你提前掌握。已经熟悉的部分可以跳过。

---

## 它不是什么

- **不是 API 文档**：如何构建、配置、运行，看 [README](../../README.md)
- **不是架构事实清单**：当前架构长什么样，看 [architecture.md](../architecture.md)
- **不是开发日志**：优化按什么顺序做的，看 [summary.md](../summary.md) 与 [changes/](../changes/)
- **不是源码逐行注释**：代码片段只保留有信息量的部分，完整实现请对照源码

它是：**一条从「功能怎么实现」到「为什么这样实现」的学习路径**。

## 关于「本项目」与「参考项目」

NovaServer 的起点是开源项目 [qinguoyi/TinyWebServer](https://github.com/qinguoyi/TinyWebServer)（MIT 协议）。但本资料**不按「原项目做什么、本项目做什么」两套体系并列讲解**，而是只讲**本项目的当前实现**：

1. 先讲这个功能现在如何工作；
2. 当某处做法是对起点的改造时，说明「最初的做法是什么 → 它为什么不够 → 改成了什么 → 结果如何」。

这样读下来，你看到的是**一个项目的完整实现与演进**，而不是两份代码的对照表。

## 阅读约定

- **术语与代码命名一致**：统一用「子 Reactor」而不是「工作线程」，统一用「文件描述符」而不是「句柄」
- **第一次出现的概念先解释再使用**：例如 `epoll`、`timerfd`、`mmap` 都会先说明它解决什么问题
- **引用源码给出文件与行号**，可直接跳转
- **性能数字注明来源与限定条件**；推测的内容明确标注「未验证」
- **代码片段只贴关键几行**，完整实现请打开源码
- **每册末尾有「通用知识」**：脱离本项目仍然成立、可以迁移到其他后端项目的部分
