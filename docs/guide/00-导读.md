# NovaServer 项目解读

> 这是一套面向**学习与理解**的项目解读资料，共 12 册。它不重复「做了什么」，而是回答「**为什么这样设计**」——每一处结构、每一个取舍、每一次踩坑，都讲清前因后果。

---

## 这是什么

一套从零开始读懂 NovaServer 的导读：从「服务器是什么」讲到「一个连接的一生」，从原项目的结构讲到二次开发的每一项改动。**假设读者会写 C++、了解基本的 socket 编程**，其余概念在需要时会就地补齐。

**它不是**：

- **不是 API 文档**——想知道怎么构建、配置、运行，看 [README](../README.md)
- **不是事实描述**——想知道当前架构长什么样，看 [architecture.md](../architecture.md)
- **不是开发日志**——想知道优化按什么顺序做的，看 [summary.md](../summary.md) 与 [changes/](../changes/)

**它是**：一条**从问题到方案**的推理链。每一章都按 STAR 组织——**背景（为什么必须处理）→ 目标（要做成什么样）→ 做法（含备选方案的取舍理由）→ 结果（数据、验证方式、代价）**。

## 项目一页速览

**NovaServer** 是一个 Linux 下的 C++17 轻量级 Web 服务器，基于开源项目 [qinguoyi/TinyWebServer](https://github.com/qinguoyi/TinyWebServer)（MIT 协议）二次开发。

| 维度 | 内容 |
|:--|:--|
| **并发模型** | 主从 Reactor（one loop per thread）：主线程只 `accept`，连接按轮转分发给子 Reactor 线程 |
| **事件源** | 全部收敛为文件描述符：`epoll` + `timerfd` + `eventfd` + `signalfd`，**全项目没有信号处理函数** |
| **功能** | 静态资源、用户注册登录（MySQL）、文件上传 |
| **验证** | 7 个 GoogleTest 目标、GitHub Actions CI、ASan / TSan / valgrind、可复现的压测数据 |

**二次开发前后的四项指标**：

| 指标 | 优化前 | 优化后 |
|:--|--:|--:|
| 默认配置 QPS | 19808 | **33151**（+67%） |
| P99 延迟 | 899.99 ms | **16.79 ms** |
| 常驻内存 | 262.8 MB | **12.6 MB**（−95%） |
| 线程数对吞吐的影响 | 无差异 | `-t1` 28372 → `-t2` **48185** |

**同时也要知道代价**：`-t1` 下吞吐回退约 12%~15%，这是新架构为每连接维护独立计时器的取舍；还有一处至今没有定论（见 [10](10-性能度量.md) §6.3）。**这套资料的写法是「连同代价一起讲」，而不是只报喜。**

## 阅读约定

- **术语与代码中的命名保持一致**，不做同义替换（如统一用「子 Reactor」而不是「工作线程」）
- **引用源码时给出文件与行号**，可直接跳转
- **性能数字一律注明来源与限定条件**；凡是推测的，明确标注「未验证」
- **代码片段只贴有信息量的几行**，完整实现请去看源码
- 每章末尾的两节是固定的：**通用知识**（可迁移的部分）与**延伸阅读**（指向 `changes/` 与源码）
