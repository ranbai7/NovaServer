# 项目文档

本目录收录 NovaServer 的设计文档与开发记录，用于沉淀项目演进过程中的技术决策与验证数据。

## 文档索引

| 文档 | 说明 |
|:--|:--|
| [ROADMAP.md](ROADMAP.md) | 优化路线图：分阶段目标、技术方案与推进进度 |
| [architecture.md](architecture.md) | 系统架构说明：并发模型、模块结构、连接生命周期 |
| [performance.md](performance.md) | 性能数据汇总：各阶段压测数据、优化前后对比与评价 |
| `changes/` | 各项优化的详细记录（随优化进展新增） |

## 记录规范

每完成一项优化，在 `changes/` 目录下新增一份记录文档，命名形如 `NNN-简述.md`（如 `001-url-path-normalization.md`），内容包含以下部分：

1. **背景与动机** — 由什么问题触发，为什么值得处理
2. **现状分析** — 现有实现的做法及其局限
3. **设计方案** — 选用的方案，以及在备选方案间的取舍理由
4. **实现要点** — 关键改动涉及的模块与文件
5. **验证** — 测试方法、观测数据与结论
6. **遗留问题** — 尚未解决的点与后续方向

性能相关的数字必须注明测试环境、编译选项与执行命令，保证可复现。

## 写作约定

- 术语与代码中的命名保持一致，避免同义替换
- 引用代码位置时给出文件路径
- 聚焦「为什么这样设计」，而非仅罗列改动内容
- 涉及架构调整的改动，同步更新 `architecture.md`

代码注释的密度约定：

- 注释回答的是「为什么这样」与「为什么不是另一种写法」。仅仅复述代码在做什么的注释不写
- **函数体内的说明压到一行**，只留结论；函数与类级别可以多写几行，交付接口契约
- 不留被注释掉的代码，也不留「新增」「此前」这类随改动过期的前缀
- 记录历史缺陷或时序约束的注释（「此前 X 导致 Y」）要保住因果，压缩时不能把结论压没
